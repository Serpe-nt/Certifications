## How this module was verified

- The owner gave the go-ahead in the session to create and delete the namespace `learn-m12` and to write to the tenant `learn-m12`, signed in to Grafana in the session's browser pane, and gave the lab seed for the token checks. The seed is not written here.
- Loki was queried through `http://10.10.0.5` with `Host: loki.lab.k8s.local` and `X-Scope-OrgID: lab` (or `learn-m12`), from Windows with a small Python script and curl, as earlier cards did. Every query of the lessons was run this way, on a range of 15 minutes or less, except where a row says otherwise (the series and volume reads of step 1 use one hour of the index only).
- `kubectl` ran in WSL (`archlinux`) with `KUBECONFIG=~/.kube/lgtm-lab.config`.
- Loki's running configuration was read from `/config` through Loki's gateway (it reaches an ingester) and saved for the session; the values quoted below come from it.
- The Loki docs were read as Markdown for version 3.7 (`https://grafana.com/docs/loki/v3.7.x/...`) on 2026-11-14.
- From about 12:50 UTC new pods on worker2 and worker3 could not start (`plugin type="calico" failed (add): error getting ClusterInformation: connection is unauthorized: Unauthorized`). That hit the second run of the burst Job (step 12). The first run, at 12:35 UTC, is the evidence below. Nothing in the lab was changed; the planner was told.
