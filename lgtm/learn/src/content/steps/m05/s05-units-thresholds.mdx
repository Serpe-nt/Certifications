<Problem>
At 2 a.m. the on-call engineer opens the checkout dashboard. A panel says 0.0312. Is that seconds or milliseconds, an error share or a count, and is it good or bad? They lose ten minutes finding out, then learn it was 3.12% of requests failing.
</Problem>

A panel that shows the right number in the wrong form still fails its reader. Most of the fix sits in a few options.

<Idea>
Display options change how Grafana shows a value, never the value itself. A unit tells the reader what the number means, thresholds colour it by how good or bad it is, and a clean legend names each line. Choosing the visualization that fits the question does the rest.
</Idea>

## Standard options: unit, range and decimals

Most visualizations share a section called **Standard options**. What you set there applies to every field in the panel. **Unit** is the most important: Grafana then formats the value for you, so 0.0312 with the unit for a share between 0 and 1 reads as 3.12%, and 0.250 in seconds reads as 250 ms. **Min** and **Max** fix the range that percentage thresholds and gauges measure against. **Decimals** sets how many decimal places to show; left empty, Grafana picks a number for you. **No value** sets the text for an empty result, a hyphen by default.

When one field of a panel needs different options, an override changes them for that field only. For example, a panel with requests and bytes can give only the bytes field the unit for bytes.

## Thresholds colour a value

A threshold is a value from which the panel turns another colour. A new panel has two: the base in green, and 80 in red. The base stands for every value below the next threshold, down to minus infinity. Thresholds can be absolute numbers or percentages of the range between Min and Max. Grafana sorts them from high to low by itself.

A stat colours its value or its background. A time series can draw thresholds as lines or filled regions behind the graph, so the reader sees how close a line came to the red zone.

## Legends name the lines

A time series names each series in its legend. In the query, the **Legend** option decides the name: **Auto** shows only the labels that differ between lines, and **Custom** prints a template you write, such as `{{span_name}}`. In the panel options, the legend can sit at the bottom or on the right, as a list or as a table, and it can add values such as the last or the maximum.

## Pick the visualization by the question

A stat or a gauge shows one value, so it needs a calculation that reduces a whole series to one number. **Last** takes the newest point, **Mean** the average over the time range. The choice changes the answer: the mean error share over a day hides a bad five minutes that **Max** would show.

  <Col title="Time series" hot>How did it change? Rates, latency and anything you compare over time.</Col>
  <Col title="Stat or gauge">What is it now? One number, coloured by thresholds.</Col>
  <Col title="Table">How do many things compare? One row per series, sortable.</Col>

<Trap practice>
A stat shows the result of its calculation. If the token looks wrong, check that the query returns exactly one series: a typo in the slot name gives no data, and a missing filter gives one stat per slot. If it shows a K, the unit is still short.
</Trap>

<Question id="q-m05-s05" answer="c">
A latency metric is recorded in milliseconds. A panel shows a typical request as 250 s, which is far too slow to be true. What went wrong?

- The query needs rate() around the metric

  rate() turns a counter into a per-second rate. It does not change the unit a value was recorded in.

- The panel needs more decimals to show the real value

  Decimals change how many digits appear after the point, not whether the value is read as seconds.

- The panel's unit is seconds while the data is in milliseconds

  A unit only labels and scales the number. Set it to the unit the data is in, here milliseconds.

- The stat calculation should be Mean instead of Last

  The calculation picks which value to show. A wrong unit stays wrong with any calculation.
</Question>
