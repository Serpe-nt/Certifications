<Problem>
A service starts to misbehave and you do not know where to look. Explore waits for a query, but you do not yet know the metric's name, which label matters or what the logs say. Writing guesses in PromQL and LogQL one by one is slow when you do not know what to ask.
</Problem>

Explore answers a question you can already write down. Before that, you often need a way to look around.

<Idea>
The Drilldown apps let you browse metrics, logs, traces and profiles by clicking. They draw a graph for each metric, label or field, so you can spot what changed and filter down to it. When you have found it, each panel opens in Explore with the query already written.
</Idea>

## Four apps, one per signal

Grafana groups the apps under **Drilldown** in the main menu. Each one works with one kind of data source.

<Layers caption="The Drilldown apps and what each reads">
  <Layer title="Metrics">Prometheus-compatible data sources, such as Prometheus and Mimir.</Layer>
  <Layer title="Logs">Loki data sources only.</Layer>
  <Layer title="Traces">Tempo, with rate, errors and duration taken from the traces.</Layer>
  <Layer title="Profiles" hot>Pyroscope, for continuous profiling.</Layer>
</Layers>

The apps used to be called Explore Metrics, Explore Logs and so on. Grafana renamed them to the Drilldown apps, so older guides may still use the old names. Like Explore, they need the permission to explore data sources.

## Metrics Drilldown: find the metric first

Metrics Drilldown opens on a grid of metrics from the data source you pick, each drawn in a way that suits its type. You narrow the grid with label filters, a search box and filters on prefixes and suffixes. When one metric looks interesting, **Select** opens it in detail. The **Breakdown** tab draws one graph per value of a label, which is often the fastest way to see which pod or which node is different. **Related metrics** shows metrics with similar names, which helps when you do not know the exact name.

## Logs Drilldown: volume, labels, fields and patterns

Logs Drilldown starts with one panel per service, ordered by log volume, each with a few recent lines. **Show logs** opens a service on its tabs. **Logs** lists the lines. **Labels** draws the log volume for each value of a stream label. **Fields** does the same for values taken from inside the lines, such as JSON keys and structured metadata. Where Loki detects patterns, a **Patterns** tab groups lines with the same shape, so you can hide the noise and keep what is unusual.

Every value can become a filter with one click, and every panel has a menu that opens its query in Explore. That is the hand-over: the app finds the place, and Explore lets you refine the query by hand.

<Compare caption="Where to start an investigation">
  <Col title="Drilldown app">You do not know the metric, label or log shape yet. Click to look around.</Col>
  <Col title="Explore" hot>You can write the question. Type the query and read the answer.</Col>
</Compare>

## Traces and profiles

Traces Drilldown builds rate, errors and duration from the spans themselves and lets you filter by attributes without TraceQL. It needs a Tempo with TraceQL metrics. Profiles Drilldown reads Pyroscope, which this lab does not run, so its app has no data source to show. Module m02 already showed how traces, logs and metrics link to each other; the later modules on Tempo come back to Traces Drilldown.

<InLab>
The beacon in `lab-tools` writes one JSON log line a minute for every check slot. In Loki, the slot is structured metadata, not a stream label, so Logs Drilldown shows it under **Fields**. The lab's Loki runs without pattern detection, so its services have no Patterns tab.
</InLab>

<Trap>
A Drilldown app shows what the data source returns for the chosen time range, nothing more. An empty grid usually means the wrong data source or a time range with no data, not a broken app.
</Trap>

<Remember>
Use a Drilldown app when you do not know what to ask yet, and Explore once you do. The panel menu takes you from one to the other with the query written for you.
</Remember>

<Do>
1. In the main menu open **Drilldown**, then **Metrics**. Pick the data source **Prometheus** and type `kube_node` in the search box.
2. On the panel of `kube_node_info`, click **Select**. The **Breakdown** tab lists the metric's labels with their values; the label `node` has seven. Click **Select** on `node` to get one graph per node.
3. Now open **Drilldown** > **Logs**. Keep the data source **Loki** and set the time range to **Last 15 minutes**. Type `beacon` in the service search field and pick it from the list. Logs Drilldown opens the service on its **Logs** tab.
4. Open the **Fields** tab. Find the field `slot` and click **Select**. Each slot of the course has its own graph, 171 in all. (The field `slot_extracted` is the same value read from the JSON body.)
5. Type `log-m05-1` in **Search for value** and click **Include** on its graph. The filter `slot = log-m05-1` appears under **Fields** at the top. Go back to the **Logs** tab: only the lines of that slot are left, one a minute.
6. Click one line to open its details. Find the token in the line's JSON, under `payload` (`token`).
7. Open the menu (three dots) of the **Log volume** panel and choose **Explore**. Explore opens with a LogQL query that counts these lines, with `| json` and `| slot="log-m05-1"` in it. Read it: this is the query you did not have to write.
8. Paste the token in the lab check below.
</Do>

<Done>
You found one slot's lines among the beacon's logs without writing a query, and you saw the query Logs Drilldown had built for you.
</Done>

<Trap practice>
The beacon writes one line a minute per slot. With a time range shorter than a minute or two you may see no line for the slot. If the service list has no beacon, widen the time range first.
</Trap>

<Question id="q-m05-s03" answer="a">
Error logs from the cart service jumped, and you want to see which pod writes most of them. You do not know which stream labels the service has. Where do you start?

- Logs Drilldown, on the Labels tab of the cart service

  The Labels tab draws the log volume per value of each label, so the noisy pod stands out without a query.

- Metrics Drilldown, with a search for the word cart

  Metrics Drilldown browses metrics. It can point to related logs, but it does not break log volume down by label.

- Explore, with a LogQL query that lists every label

  Explore can do it once you know what to ask. Here you do not yet know the label names.

- A new dashboard with a logs panel for the cart service

  A dashboard is for questions you ask again. Building one first is the slow way to look around.
</Question>
