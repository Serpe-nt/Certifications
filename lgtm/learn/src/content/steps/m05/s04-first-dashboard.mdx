<Problem>
Every morning the checkout team opens Explore and types the same three queries to see whether the night was quiet. One of them always has a typo. Someone suggests keeping the queries in a text file. Someone else asks why the answers cannot be waiting for them on one page.
</Problem>

A question you ask every day deserves a saved answer. That is what a dashboard is for.

<Idea>
A dashboard is a saved page of panels. Each panel holds one or more queries and draws their result as a visualization: a graph, a big number, a table. You build a panel once in the panel editor, save the dashboard into a folder, and from then on the answers are there when you open it.
</Idea>

## A folder first

Folders group dashboards, and permissions set on a folder pass to every dashboard in it. In a Grafana that many people share, your work goes into a folder of its own. Then nothing that someone else set up is touched, and one delete cleans up. A folder name cannot contain an underscore or a percent sign.

Some dashboards come from files, like the lab's data sources. These provisioned dashboards cannot be saved from the screen unless the setup allows it. When you try, the **Save dashboard** drawer says the dashboard cannot be saved from the Grafana UI because it was provisioned from another source, and offers its JSON to copy or to save as a file. To change one, you save a copy under a new name or change the file it came from.

## Inside the panel editor

When you configure a new panel, Grafana opens the panel editor. Its parts follow the path data takes. The **Queries** tab at the bottom picks the data source and holds the queries; a new panel starts with the default data source. The preview in the middle shows the result, and the switch **Table view** shows the panel's data as a plain table, which helps when a graph looks wrong. On the right, you pick the visualization and set its options.

Grafana looks at the result and suggests visualizations that fit its shape. The default and most used one is **Time series**, a graph of values over time. **Stat** shows one big number with an optional small graph behind it. **Table** shows rows and columns. Each visualization has its own options; the next step covers the ones every panel shares.

## A rate that works at every zoom

On a dashboard the time range changes all the time, so a fixed window such as `[5m]` in `rate()` fits some zooms and not others. Grafana offers `$__rate_interval` for this. It is the larger of the panel's step plus one scrape interval, and four scrape intervals. That keeps at least four samples inside each window. Grafana takes the scrape interval from the data source settings.

## Saved means saved

**Back** in the panel editor returns to the dashboard with your changes applied but not saved. Only **Save** writes the dashboard. The first save asks for a title and a folder, and Grafana gives the dashboard a UID: the ID that its address carries after `/d/`, and that links to it use.

<InLab>
The lab's data source **Mimir** has a scrape interval of 30 seconds, so `$__rate_interval` is never shorter than two minutes there. The shop's request metrics come from Tempo's span metrics as `traces_spanmetrics_calls_total`, with the label `service_name`.
</InLab>

<Trap>
**Back** does not save. If you close the tab after **Back**, the panel is gone. Watch for the dashboard's unsaved-changes warning, and save before you leave.
</Trap>

<Remember>
Put your dashboards in a folder of your own, use `$__rate_interval` in `rate()`, and save before you leave the page.
</Remember>

<Question id="q-m05-s04" answer="b">
You edited a panel, clicked Back, and closed the browser tab. The next day the change is gone. Why?

- Panels are reset each night from the data source

  Grafana does not reset panels. The panel was never written to the dashboard.

- Back returns to the dashboard without saving it

  Back applies your edits to the open dashboard only. Save is what writes them.

- Only an administrator can save a panel

  An editor of the folder can save. The missing step was the save itself.

- The panel's query used $__rate_interval

  The variable changes the rate window, not whether the dashboard is saved.
</Question>
