<Problem>
The checkout dashboard works well, so the payment team copies it and replaces "checkout" in every query. Then the cart team does the same. Six weeks later there are twelve copies, a fix to one panel reaches only one of them, and nobody knows which copy is current.
</Problem>

The twelve copies differ in one word. That word should be something the viewer chooses, not something written into every query.

<Idea>
A variable is a placeholder that the viewer sets from a drop-down list at the top of the dashboard. You write `$service` in the queries once, and Grafana puts in the chosen value before it sends each query. One dashboard then serves every service, and a fix reaches all of them at once.
</Idea>

## Where the values come from

The most useful kind is the query variable: its values come from a query to a data source. For a Prometheus data source, the query type **Label values** asks for every value of one label, optionally only on one metric. Other types return label names, metric names or the result of a PromQL query. The older form `label_values(metric, label)` still exists as **Classic query**, and Grafana marks it as deprecated.

Other kinds fill the list in other ways. A custom variable takes a fixed, comma-separated list. A text box lets the viewer type a value. A data source variable lists data sources of one type, so the same dashboard can point at another Prometheus.

<Compare caption="Three kinds of variable you will use most">
  <Col title="Query" hot>Values from the data source, so a new service appears by itself.</Col>
  <Col title="Custom">A fixed list you type, such as 50, 95, 99 for percentiles.</Col>
  <Col title="Data source">The data sources of one type, to switch backend or tenant.</Col>
</Compare>

**Refresh** sets when Grafana reloads the values: on every dashboard load, or also when the time range changes. **Sort** orders the list. Without a default, the first value in the list is selected when the dashboard opens.

## How a variable reaches the query

Before a query leaves Grafana, it is interpolated: every `$service` or `${service}` is replaced by the current value. The braces are needed when the variable sits inside a word. The old form `[[service]]` is deprecated.

A variable can allow several values at once (**Multi-value**) and offer an **All** option. Grafana then joins the values for the query language. For Prometheus it builds a regular expression, so the label matcher must be `=~`, not `=`. The chosen values also go into the page's address, so a link you share opens with the same selection.

## Repeating panels

With a multi-value variable, one panel can stand for many. Under **Repeat options**, choose the variable to repeat by, and Grafana draws a copy of the panel for each selected value, side by side or in a column. Only the first panel can be edited; its copies follow it. Put the variable in the title, so each copy says which value it shows.

<InLab>
The span metrics of the shop carry the service in the label `service_name`, so one Label values query on `traces_spanmetrics_calls_total` lists every shop service that has sent a span.
</InLab>

<Trap>
A single-value query written as `service_name="$service"` breaks the moment someone turns on Multi-value, because two values become a regular expression. Use `=~` wherever a variable might hold more than one value.
</Trap>

<Remember>
One dashboard with a variable beats many copies. Write the variable in the queries and the titles, and use `=~` when it may hold several values.
</Remember>

<Do>
1. Open your dashboard `Shop service (m05)` and click **Edit**. In the toolbar on the right, click the **Options** icon (a cog) to open the dashboard's sidebar, and click **+** next to **Variables**. Choose the type **Query**.
2. In the sidebar, set **Name** to `service` and **Label** to `Service`. Leave **Refresh** at **On dashboard load**. Click **Open variable editor**.
3. In the window **Query variable: service**, keep **Mimir** as the data source and set **Query type** to **Label values**. Set **Metric** to `traces_spanmetrics_calls_total` and **Label** to `service_name`. Set **Sort** to **Alphabetical (asc)** and click **Run query**: the preview lists the shop's services. Click **Apply**, then **Save** the dashboard at once.
4. Edit the panel Requests per second. In its query, replace `service_name="checkout"` with `service_name=~"$service"`, and change the title to `Requests per second: $service`. Do the same in the panel Error share (both places in its query, title `Error share: $service`). Save.
5. Pick **payment** in the Service drop-down at the top. Both panels redraw for the payment service, and the address bar now holds `var-service=payment`.
6. Try a repeat: open the variable again (sidebar, **Variables**, the pencil next to `service`) and turn on **Multi-value**. Select the panel Error share and, under **Repeat options**, set **Repeat by variable** to `service`. The sidebar warns that repeats are not visible in edit mode: save, click **Exit edit**, and select cart, checkout and payment in the drop-down. Error share now appears three times, once per service.
7. Undo the repeat: in edit mode, set **Repeat by variable** back to **Disable repeating**, turn **Multi-value** off, select **checkout** and save.
8. Open the drop-down and paste its first value in the lab check below.
</Do>

<Done>
The dashboard has a Service variable whose values come from Mimir, both panels follow it, and the choice shows in the address bar.
</Done>

<Trap practice>
Save after you apply a variable. A variable that was applied but not saved is gone if you leave or reload the page. If the drop-down is empty, check the variable's data source and the dashboard's time range; if a panel shows no data after the change, look for a leftover `=` before `"$service"`.
</Trap>

<Question id="q-m05-s06" answer="a">
A dashboard has a variable cluster with values from Mimir. A new cluster starts sending metrics, but it is not in the drop-down until someone reopens the dashboard. Which setting explains this?

- Refresh is set to On dashboard load

  With this setting Grafana fetches the values only when the dashboard loads. A new value appears on the next load.

- Sort is set to Disabled

  Sort only changes the order of the values. It does not decide whether a new value is fetched.

- The variable is not Multi-value

  Multi-value lets a viewer pick several values. It has nothing to do with when the list is refreshed.

- The query type is Label values

  Label values does return every value of the label. When it runs is set by Refresh.
</Question>
