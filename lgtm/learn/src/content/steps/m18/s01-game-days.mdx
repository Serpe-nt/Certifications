<Problem>
In module m14 every incident had a title, such as "some orders fail at checkout", and you knew which flag the step had switched on. On call you get neither. A graph turns red, and the fault could be anywhere in ten services. The only way to practise that is to let something break that you did not choose.
</Problem>

<Idea>
A game day puts a fault into the system on purpose, and you find it as if it were real. A small script picks one fault at random and switches it on without telling you which. You find it with the method of module m14, write one line (service, symptom, cause), and only then ask the script what it was.
</Idea>

<Flow caption="One round">
  <Stage title="Start" kicker="Script">One fault on, name hidden; the guard starts.</Stage>
  <Stage title="Find" kicker="Method">Symptom, metric, trace, log, cause.</Stage>
  <Stage title="Write" kicker="One line">Service, symptom, cause, and the evidence.</Stage>
  <Stage title="Reveal" kicker="Script">Off, proved off, and what it was.</Stage>
</Flow>

## How a round runs

You play three rounds. In each, `gameday.py start` reads the flag screen's API and refuses to start while any flag is on, or while the shop is still in its quiet time after the last round. Then it picks one fault from its list, writes the choice and the time into `~/gameday.json`, switches the fault on, and prints only the time. From there you work as on call: find the symptom, narrow it with a metric, open one trace, read its logs, and test your guess. When one piece of evidence explains the symptom, write your line. Then `gameday.py reveal` puts the flag back to the value it saved, reads the API again to prove that every flag is off, and prints what it was and how long it ran.

Every change goes the same way, because a write to the API replaces the whole flag document: read it, change one flag, read it again to check that nobody changed it in the meantime, write, and read once more to prove that exactly that flag changed. The API cannot refuse a write that comes too late, so the check narrows the gap before the write and catches most clashes; it cannot rule one out. If the last read shows anything else than what was written, the script stops and says so. The script reads a flag with a rule, such as `productCatalogFailure`, as on when either branch of the rule is on; like the flag screen, it switches only the first branch.

Do not open `~/gameday.json` or the flag screen during a round; both tell you the answer. The flag screen also has a Scheduler tab that switches random flags on and off by itself; it shows which ones it picked, so it is no use for a game day. The SRE book says the same about real incidents: start from what users see, and test each guess against the system rather than against what you expect.

## The faults in the draw

The script draws from six faults. Each is one that an earlier module switched on in this lab and watched heal after it was switched off: payment refusing a share of charges, checkout unable to reach payment, product-catalog failing for one product, a lock in product-catalog's database, extra copies of every order in Kafka, and cart failing its readiness probe. They show in different places: some as errors, one first as latency, one as lag on a queue, one in the cluster's own state. So do not look only for errors.

Ten other flags are left out. `recommendationCacheFailure` makes recommendation run out of memory and restart again and again, and the restart count stays behind. `imageSlowLoad` shows only in a browser that loads product images. `cartFailure` fails a call whose error checkout ignores, so nothing a user sees changes. `emitRawPii` changes what spans carry, not how the shop behaves. `cartMetricCardinalityOverflow` leaves thousands of series behind in Mimir. `loadGeneratorFloodHomepage` adds load to the whole lab, which other users of the lab would feel. `adFailure`, `adHighCpu`, `adManualGc` and `kafkaConsumerDead` were never switched on in this course, so you would not know what normal and broken look like for them.

## The guard, and the rules of the shared lab

A flag is never on for longer than 15 minutes. Before `start` switches the fault on, it starts a pod named `gameday-guard` in the namespace `learn-m18`. The pod waits 15 minutes from its own start and then switches every flag of the draw off, so the fault, switched on a few seconds later, never runs the full 15 minutes. It only ever switches flags off, and when the API does not answer, for example while the shop's proxy restarts, it keeps trying for 20 minutes. It runs in the cluster, so it works even if you close the terminal, WSL stops or you walk away; `reveal` deletes it. If the guard was first, `reveal` says so: the round ran out of time. If a flag is still on after `reveal`, it says so and ends with an error. The pod's definition holds the script and nothing about which fault is on.

The lab is shared, so the usual rules hold: one flag at a time in the whole lab, and ten quiet minutes between rounds so that the next round starts from a quiet shop. The script refuses to start while any flag is on, and it keeps ten quiet minutes after its own last round, which it knows from `~/gameday.json`. It cannot know when someone else last switched a flag: look at the dashboards before you start. A quiet shop still shows error spans, on purpose: every 10 minutes the flag streams of ad, fraud-detection and recommendation end with DEADLINE_EXCEEDED. Leave them out of every search for errors with `&& name != "flagd.evaluation.v2.Service/EventStream"`.

## Score yourself

After each reveal, compare your line with the fault. The service is right if you named the one where the fault lives, not just the one where users noticed it. The cause is right if your evidence would convince someone who was not there: a status message, a span, a log line, a metric that moved. Note the minutes from start to your line. Three rounds with three right lines and evidence are a good result; a wrong one tells you which link of the method to practise.

<Do>
1. Open WSL, type `bash`, and point kubectl at the lab: <Cmd>{`export KUBECONFIG=~/.kube/lgtm-lab.config`}</Cmd> Check that the namespace `shop` answers: <Cmd>{`kubectl -n shop get deploy flagd`}</Cmd>
2. Save this file as `gameday.py` in your home folder. You may read it; it does not print which fault it picks.

   ```python
   #!/usr/bin/env python3
   # Game day for the lab: one fault you do not know, found with the method, then revealed.
   #   python3 gameday.py start    refuse if any flag is on; switch one fault on; start the guard
   #   python3 gameday.py reveal   put the flag back, prove every flag is off, say what it was
   # The guard is a pod in learn-m18 that switches every game-day flag off after 15 minutes,
   # also when this terminal or WSL is closed. It holds no hint of which fault is on.
   import copy, datetime, json, os, random, subprocess, sys, time, urllib.request

   API = os.environ.get("FLAG_API", "http://10.10.0.5/feature/api")
   HOST = os.environ.get("FLAG_HOST", "flags.lab.k8s.local")
   STATE = os.path.expanduser("~/gameday.json")
   LIMIT = 15 * 60   # a flag is never on longer than this
   QUIET = 10 * 60   # quiet time after a round, before the next one
   FAULTS = {
       "paymentFailure": "50%",
       "paymentUnreachable": "on",
       "productCatalogFailure": "on",
       "productCatalogLockContention": "on",
       "kafkaQueueProblems": "on",
       "failedReadinessProbe": "on",
   }

   def call(path, body=None):
       headers = {"Content-Type": "application/json"}
       if HOST:
           headers["Host"] = HOST
       data = json.dumps({"data": body}).encode() if body is not None else None
       req = urllib.request.Request(API + path, data=data, headers=headers)
       with urllib.request.urlopen(req, timeout=10) as r:
           return json.load(r)

   def variant(flag):
       # A flag with a rule "if CONDITION then A else B" (productCatalogFailure) is on when A or B is.
       rule = flag.get("targeting", {}).get("if")
       if isinstance(rule, list) and len(rule) == 3:
           return rule[1] if rule[1] != "off" else rule[2]
       return flag["defaultVariant"]

   def switch(doc, name, value):
       flag = doc["flags"][name]
       rule = flag.get("targeting", {}).get("if")
       if isinstance(rule, list) and len(rule) == 3:
           rule[1] = value
       else:
           flag["defaultVariant"] = value

   def flags_on(doc):
       return sorted(n for n, f in doc["flags"].items() if variant(f) != "off")

   def changed(a, b):
       names = set(a["flags"]) | set(b["flags"])
       return {n for n in names if a["flags"].get(n) != b["flags"].get(n)}

   class NotWritten(SystemExit):
       pass

   def change(wanted):
       # wanted: {flag: variant}. Read, change only these flags, write, read again and prove it.
       # A write replaces the whole document, so stop if anyone changed it since our read. The API has
       # no compare-and-set: this narrows the gap before the write, it cannot close it.
       before = call("/read")
       after = copy.deepcopy(before)
       for name, value in wanted.items():
           switch(after, name, value)
       expected = changed(before, after)
       if call("/read") != before:
           raise NotWritten("Stopped: the flags changed while this script was working. Nothing written.")
       call("/write", after)
       now = call("/read")
       if changed(before, now) != expected or any(variant(now["flags"][n]) != v for n, v in wanted.items()):
           raise SystemExit("Stopped: after the write the flags differ from what was written. Read the flag screen.")
       return before, now

   def utc(t):
       return datetime.datetime.fromtimestamp(t, datetime.timezone.utc).strftime("%H:%M:%S UTC")

   def load():
       try:
           with open(STATE) as f:
               return json.load(f)
       except FileNotFoundError:
           return {}

   def save(state):
       with open(STATE, "w") as f:
           json.dump(state, f)

   def guard():
       # Runs in the pod: wait, then switch every game-day flag that is on back to off. It only ever
       # switches flags off, and keeps trying for 20 minutes through any error (a restarting proxy).
       time.sleep(LIMIT)
       for attempt in range(120):
           try:
               on = [n for n in flags_on(call("/read")) if n in FAULTS]
               if not on:
                   print(utc(time.time()), "guard: no game-day flag is on", flush=True)
                   return
               change({n: "off" for n in on})
               print(utc(time.time()), "guard: switched off:", ", ".join(on), flush=True)
           except BaseException as e:
               print(utc(time.time()), "guard:", repr(e), "trying again in 10 s", flush=True)
               time.sleep(10)
       raise SystemExit("guard: could not switch the flags off")

   def kubectl(*args, stdin=None):
       return subprocess.run(["kubectl", *args], input=stdin, text=True, capture_output=True)

   def start_guard():
       me = open(os.path.abspath(__file__)).read()
       pod = {
           "apiVersion": "v1", "kind": "Pod",
           "metadata": {"name": "gameday-guard", "namespace": "learn-m18"},
           "spec": {
               "restartPolicy": "Never",
               "containers": [{
                   "name": "guard",
                   "image": "docker.io/library/python:3.14.7-alpine3.24",
                   "command": ["python", "-u", "-c", "import os; exec(os.environ['SCRIPT'])", "guard"],
                   "env": [
                       {"name": "SCRIPT", "value": me},
                       {"name": "FLAG_API", "value": "http://frontend-proxy.shop.svc:8080/feature/api"},
                       {"name": "FLAG_HOST", "value": ""},
                   ],
                   "resources": {"requests": {"cpu": "10m", "memory": "32Mi"},
                                 "limits": {"cpu": "100m", "memory": "64Mi"}},
               }],
           },
       }
       kubectl("create", "namespace", "learn-m18")
       kubectl("-n", "learn-m18", "delete", "pod", "gameday-guard", "--ignore-not-found", "--wait=true")
       r = kubectl("apply", "-f", "-", stdin=json.dumps(pod))
       if r.returncode != 0:
           return r.stderr.strip()
       r = kubectl("-n", "learn-m18", "wait", "pod/gameday-guard", "--for=condition=Ready", "--timeout=120s")
       if r.returncode == 0:
           return None
       kubectl("-n", "learn-m18", "delete", "pod", "gameday-guard", "--ignore-not-found", "--wait=false")
       return r.stderr.strip() or "the guard pod was not ready after 120 s"

   def start():
       state = load()
       if state.get("flag"):
           sys.exit("A round is open since " + utc(state["started"]) + ". Run reveal first.")
       wait = state.get("ended", 0) + QUIET - time.time()
       if wait > 0:
           sys.exit("Keep the shop quiet for %d more minutes before the next round." % (wait // 60 + 1))
       on = flags_on(call("/read"))
       if on:
           sys.exit("Not started: these flags are on already: " + ", ".join(on))
       # The guard starts first, so its 15 minutes end before the fault's do.
       problem = start_guard()
       if problem:
           sys.exit("The guard did not start, so no fault was switched on: " + problem)
       name = random.choice(sorted(FAULTS))
       now = time.time()
       # Saved before the write, so that reveal can always put the flag back.
       save({"flag": name, "variant": FAULTS[name], "was": "off", "started": now})
       try:
           change({name: FAULTS[name]})
       except NotWritten:
           kubectl("-n", "learn-m18", "delete", "pod", "gameday-guard", "--ignore-not-found", "--wait=false")
           save({"ended": now})
           raise
       except BaseException:
           # The write may have happened: keep the guard and the state, and let reveal clean up.
           print("Something went wrong after the write. Run reveal; the guard stays until then.")
           raise
       print("Round started at %s. A fault is on." % utc(now))
       print("The guard switches it off at %s at the latest. Reveal when you have your line." % utc(now + LIMIT))

   def reveal():
       state = load()
       if not state.get("flag"):
           sys.exit("No round is open.")
       name = state["flag"]
       if variant(call("/read")["flags"][name]) == state["was"]:
           now = call("/read")
           phase = kubectl("-n", "learn-m18", "get", "pod", "gameday-guard", "-o", "jsonpath={.status.phase}").stdout
           if phase == "Succeeded":
               note = "The guard had already switched it off, within 15 minutes of the start. The round ran out of time."
           else:
               note = "It was already off, and the guard has not run: someone else switched it, or the start's write did not land."
       else:
           _, now = change({name: state["was"]})
           note = "Switched off at %s, after %.1f minutes." % (utc(time.time()), (time.time() - state["started"]) / 60)
       kubectl("-n", "learn-m18", "delete", "pod", "gameday-guard", "--ignore-not-found", "--wait=false")
       save({"ended": time.time()})
       print("The fault was %s = %s, on from %s." % (name, state["variant"], utc(state["started"])))
       print(note)
       on = flags_on(now)
       print("Flags on now:", ", ".join(on) or "none")
       if on:
           sys.exit("Not done: a flag is still on. Switch it off on the flag screen.")

   if __name__ == "__main__":
       command = {"start": start, "reveal": reveal, "guard": guard}.get(sys.argv[1] if sys.argv[1:] else "")
       if not command:
           sys.exit("usage: python3 gameday.py start | reveal")
       command()
   ```

<Trap practice>
If `reveal` prints that the guard had already switched the fault off, your round took longer than 15 minutes. Count it as unsolved, and take the next round with the method in a stricter order. If `start` says a round is open after a break, run `reveal` first: the script remembers the open round in `~/gameday.json`. If either command stops because the flags changed while it worked, someone else is using the flag screen: wait a few minutes and run it again.
</Trap>

<Remember>
A game day trains what a scripted incident cannot: finding the place of a fault you did not choose. Write your line before the reveal, and score it by its evidence.
</Remember>

<Question id="q-m18-s01" answer="c">
During a round, checkout's dashboard shows failed orders. In an order's trace the first failing span is a checkout client span to payment of a few microseconds, with code UNAVAILABLE and no payment server span below it. Which line should you write?

- checkout: orders fail, because PlaceOrder has a bug

  Nothing in the trace shows a bug in PlaceOrder. It shows only that checkout's call to payment never arrived.

- payment: orders fail, because payment refuses the charges

  If payment had refused them, a payment server span with its own error would be in the trace.

- checkout to payment: orders fail, the calls never arrive

  A client span of microseconds with UNAVAILABLE and no server span means the call never arrived.

- frontend: orders fail, because its API answers with an error

  The frontend shows the symptom. The trace leads further down to the failing call.
</Question>
