<Problem>
In module m14 every incident had a title, such as "some orders fail at checkout", and you knew which flag the step had switched on. On call you get neither. A graph turns red, and the fault could be anywhere in ten services. The only way to practise that is to let something break that you did not choose.
</Problem>

<Idea>
A game day puts a fault into the system on purpose, and you find it as if it were real. A small script picks one fault at random and switches it on without telling you which. You find it with the method of module m14, write one line (service, symptom, cause), and only then ask the script what it was.
</Idea>

<Flow caption="One round">
  <Stage title="Start" kicker="Script">One fault on, name hidden; the guard starts.</Stage>
  <Stage title="Find" kicker="Method">Symptom, metric, trace, log, cause.</Stage>
  <Stage title="Write" kicker="One line">Service, symptom, cause, and the evidence.</Stage>
  <Stage title="Reveal" kicker="Script">Off, proved off, and what it was.</Stage>
</Flow>

## How a round runs

You play three rounds. In each, `gameday.py start` reads the flag screen's API and refuses to start while any flag is on, or while the shop is still in its quiet time after the last round. Then it picks one fault from its list, switches it on, writes the choice and the time into `~/gameday.json`, and prints only the time. From there you work as on call: find the symptom, narrow it with a metric, open one trace, read its logs, and test your guess. When one piece of evidence explains the symptom, write your line. Then `gameday.py reveal` switches the fault off, reads the API again to prove that every flag is off, and prints what it was and how long it ran.

Do not open `~/gameday.json` or the flag screen during a round; both tell you the answer. The SRE book says the same about real incidents: start from what users see, and test each guess against the system rather than against what you expect.

## The faults in the draw

The script draws from six faults. Each is one that an earlier module switched on in this lab and watched heal after it was switched off: payment refusing a share of charges, checkout unable to reach payment, product-catalog failing for one product, a lock in product-catalog's database, extra copies of every order in Kafka, and cart failing its readiness probe. They show in different places: some as errors, some only as latency, one as lag on a queue, one in the cluster's own state. So do not look only for errors.

Ten other flags are left out. `recommendationCacheFailure` makes recommendation run out of memory and restart again and again, and the restart count stays behind. `imageSlowLoad` shows only in a browser that loads product images. `cartFailure` fails a call whose error checkout ignores, so nothing a user sees changes. `emitRawPii` changes what spans carry, not how the shop behaves. `cartMetricCardinalityOverflow` leaves thousands of series behind in Mimir. `loadGeneratorFloodHomepage` adds load to the whole lab, which other users of the lab would feel. `adFailure`, `adHighCpu`, `adManualGc` and `kafkaConsumerDead` were never switched on in this course, so you would not know what normal and broken look like for them.

## The guard, and the rules of the shared lab

A flag is never on for longer than 15 minutes. When `start` switches the fault on, it also starts a pod named `gameday-guard` in the namespace `learn-m18`. The pod waits 15 minutes and then switches every flag of the draw off. It runs in the cluster, so it works even if you close the terminal, WSL stops or you walk away; `reveal` deletes it. The pod's definition holds the script and nothing about which fault is on.

The lab is shared, so the usual rules hold: one flag at a time in the whole lab, and ten quiet minutes between rounds so that the next round starts from a quiet shop. The script enforces both. A quiet shop still shows error spans, on purpose: every 10 minutes the flag streams of ad, fraud-detection and recommendation end with DEADLINE_EXCEEDED. Leave them out of every search for errors with `&& name != "flagd.evaluation.v2.Service/EventStream"`.

## Score yourself

After each reveal, compare your line with the fault. The service is right if you named the one where the fault lives, not just the one where users noticed it. The cause is right if your evidence would convince someone who was not there: a status message, a span, a log line, a metric that moved. Note the minutes from start to your line. Three rounds with three right lines and evidence are a good result; a wrong one tells you which link of the method to practise.

<Do>
1. Open WSL, type `bash`, and point kubectl at the lab: <Cmd>{`export KUBECONFIG=~/.kube/lgtm-lab.config`}</Cmd> Check that the namespace `shop` answers: <Cmd>{`kubectl -n shop get deploy flagd`}</Cmd>
2. Save this file as `gameday.py` in your home folder. You may read it; it does not print which fault it picks.

   ```python
   #!/usr/bin/env python3
   # Game day for the lab: one fault you do not know, found with the method, then revealed.
   #   python3 gameday.py start    refuse if any flag is on; switch one fault on; start the guard
   #   python3 gameday.py reveal   switch it off, prove every flag is off, say what it was
   # The guard is a pod in learn-m18 that switches every game-day flag off after 15 minutes,
   # also when this terminal or WSL is closed. It holds no hint of which fault is on.
   import datetime, json, os, random, subprocess, sys, time, urllib.request

   API = os.environ.get("FLAG_API", "http://10.10.0.5/feature/api")
   HOST = os.environ.get("FLAG_HOST", "flags.lab.k8s.local")
   STATE = os.path.expanduser("~/gameday.json")
   LIMIT = 15 * 60   # a flag is never on longer than this
   QUIET = 10 * 60   # quiet time after a round, before the next one
   FAULTS = {
       "paymentFailure": "50%",
       "paymentUnreachable": "on",
       "productCatalogFailure": "on",
       "productCatalogLockContention": "on",
       "kafkaQueueProblems": "on",
       "failedReadinessProbe": "on",
   }

   def call(path, body=None):
       headers = {"Content-Type": "application/json"}
       if HOST:
           headers["Host"] = HOST
       data = json.dumps({"data": body}).encode() if body is not None else None
       req = urllib.request.Request(API + path, data=data, headers=headers)
       with urllib.request.urlopen(req, timeout=10) as r:
           return json.load(r)

   def variant(flag):
       # A flag with a targeting rule (productCatalogFailure) is on through the rule's first branch.
       rule = flag.get("targeting", {}).get("if")
       return rule[1] if isinstance(rule, list) and len(rule) == 3 else flag["defaultVariant"]

   def switch(doc, name, value):
       flag = doc["flags"][name]
       rule = flag.get("targeting", {}).get("if")
       if isinstance(rule, list) and len(rule) == 3:
           rule[1] = value
       else:
           flag["defaultVariant"] = value

   def flags_on():
       doc = call("/read")
       return doc, sorted(n for n, f in doc["flags"].items() if variant(f) != "off")

   def utc(t):
       return datetime.datetime.fromtimestamp(t, datetime.timezone.utc).strftime("%H:%M:%S UTC")

   def load():
       try:
           with open(STATE) as f:
               return json.load(f)
       except FileNotFoundError:
           return {}

   def save(state):
       with open(STATE, "w") as f:
           json.dump(state, f)

   def guard():
       # Runs in the pod: wait, then switch every game-day flag off.
       time.sleep(LIMIT)
       doc, on = flags_on()
       for name in FAULTS:
           switch(doc, name, "off")
       call("/write", doc)
       print(utc(time.time()), "guard: game-day flags off; were on:", ", ".join(on) or "none", flush=True)

   def kubectl(*args, stdin=None):
       return subprocess.run(["kubectl", *args], input=stdin, text=True, capture_output=True)

   def start_guard():
       me = open(os.path.abspath(__file__)).read()
       pod = {
           "apiVersion": "v1", "kind": "Pod",
           "metadata": {"name": "gameday-guard", "namespace": "learn-m18"},
           "spec": {
               "restartPolicy": "Never",
               "containers": [{
                   "name": "guard",
                   "image": "docker.io/library/python:3.14.7-alpine3.24",
                   "command": ["python", "-u", "-c", "import os; exec(os.environ['SCRIPT'])", "guard"],
                   "env": [
                       {"name": "SCRIPT", "value": me},
                       {"name": "FLAG_API", "value": "http://frontend-proxy.shop.svc:8080/feature/api"},
                       {"name": "FLAG_HOST", "value": ""},
                   ],
                   "resources": {"requests": {"cpu": "10m", "memory": "32Mi"},
                                 "limits": {"cpu": "100m", "memory": "64Mi"}},
               }],
           },
       }
       kubectl("create", "namespace", "learn-m18")
       kubectl("-n", "learn-m18", "delete", "pod", "gameday-guard", "--ignore-not-found", "--wait=true")
       r = kubectl("apply", "-f", "-", stdin=json.dumps(pod))
       if r.returncode != 0:
           return r.stderr.strip()
       r = kubectl("-n", "learn-m18", "wait", "pod/gameday-guard", "--for=condition=Ready", "--timeout=120s")
       return None if r.returncode == 0 else r.stderr.strip()

   def start():
       state = load()
       if state.get("flag"):
           sys.exit("A round is open since " + utc(state["started"]) + ". Run reveal first.")
       wait = state.get("ended", 0) + QUIET - time.time()
       if wait > 0:
           sys.exit("Keep the shop quiet for %d more minutes before the next round." % (wait // 60 + 1))
       doc, on = flags_on()
       if on:
           sys.exit("Not started: these flags are on already: " + ", ".join(on))
       name = random.choice(sorted(FAULTS))
       switch(doc, name, FAULTS[name])
       call("/write", doc)
       now = time.time()
       save({"flag": name, "variant": FAULTS[name], "started": now})
       problem = start_guard()
       if problem:
           doc, _ = flags_on()
           switch(doc, name, "off")
           call("/write", doc)
           save({"ended": now})
           sys.exit("The guard did not start, so the fault is off again: " + problem)
       print("Round started at %s. A fault is on." % utc(now))
       print("The guard switches it off at %s at the latest. Reveal when you have your line." % utc(now + LIMIT))

   def reveal():
       state = load()
       if not state.get("flag"):
           sys.exit("No round is open.")
       doc, _ = flags_on()
       name, was_on = state["flag"], variant(doc["flags"][state["flag"]]) != "off"
       switch(doc, name, "off")
       call("/write", doc)
       now = time.time()
       _, on = flags_on()
       kubectl("-n", "learn-m18", "delete", "pod", "gameday-guard", "--ignore-not-found", "--wait=false")
       save({"ended": now})
       print("The fault was %s = %s, on from %s." % (name, state["variant"], utc(state["started"])))
       if was_on:
           print("Switched off at %s, after %.1f minutes." % (utc(now), (now - state["started"]) / 60))
       else:
           print("The guard had already switched it off.")
       print("Flags on now:", ", ".join(on) or "none")

   if __name__ == "__main__":
       command = {"start": start, "reveal": reveal, "guard": guard}.get(sys.argv[1] if sys.argv[1:] else "")
       if not command:
           sys.exit("usage: python3 gameday.py start | reveal")
       command()
   ```

<Trap practice>
If `reveal` prints that the guard had already switched the fault off, your round took longer than 15 minutes. Count it as unsolved, and take the next round with the method in a stricter order. If `start` says a round is open after a break, run `reveal` first: the script remembers the open round in `~/gameday.json`.
</Trap>

<Remember>
A game day trains what a scripted incident cannot: finding the place of a fault you did not choose. Write your line before the reveal, and score the evidence, not the guess.
</Remember>

<Question id="q-m18-s01" answer="c">
During a round, checkout's dashboard shows failed orders. In an order's trace the first failing span is a checkout client span to payment of a few microseconds, with code UNAVAILABLE and no payment server span below it. Which line should you write?

- checkout: orders fail, because PlaceOrder has a bug

  checkout's span is only the caller here. Its status says the call never reached a server.

- payment: orders fail, because payment refuses the charges

  If payment had refused them, a payment server span with its own error would be in the trace.

- checkout to payment: orders fail, because the call never reaches payment

  A client span of microseconds with UNAVAILABLE and no server span means the call never arrived.

- frontend: orders fail, because its API answers with an error

  The frontend shows the symptom. The trace leads further down to the failing call.
</Question>
