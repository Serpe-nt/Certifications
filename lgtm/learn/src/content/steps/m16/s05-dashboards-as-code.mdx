<Problem>
The lab has one RED dashboard per shop service: eleven dashboards that differ only in the service name. Someone who wants a new panel in all of them must change eleven files the same way, or one template and a loop. Old tutorials name Grafonnet and Grizzly for this. Which tools does Grafana point to today?
</Problem>

<Idea>
Every way of keeping dashboards as code ends in the same thing: the dashboard's JSON model. The tools differ in where that JSON comes from (written by hand, exported, or printed by a program) and in what brings it into Grafana (provisioning, Git Sync, Terraform, the Operator or a command-line tool). Pick one of each, for each team, and keep to it.
</Idea>

## One JSON model, two shapes

A dashboard is a JSON document. Grafana 13 knows two shapes of it. The classic shape is the one the lab's files use: a `title`, a `uid` and a list of `panels`. The newer shape is a Kubernetes-style resource with `apiVersion: dashboard.grafana.app/v2`, `kind`, `metadata` and `spec`, which you saw under **Edit as code** in module m05. Grafana 12 added these versioned APIs, and the newer tools are built on them. Dynamic dashboards, with tabs and conditional rows, exist only in the new shape.

## Where the JSON comes from

The simplest source is the screen: build the dashboard, then export its JSON and commit it. That is how most teams start, and how the lab's dashboards were made. It does not scale to eleven nearly equal dashboards.

For that, Grafana recommends the Foundation SDK. It is a set of typed builder libraries for Go, TypeScript, Python, PHP and Java. You write a program that builds a dashboard, panel by panel, and prints its JSON. A loop over a list of services gives one panel or one dashboard per service, and the language's type checks catch a wrong option before Grafana sees it. Grafonnet, the Jsonnet library many guides still show, is not officially supported; the documentation sends you to the Foundation SDK instead.

## What brings it into Grafana

<Compare caption="Ways to bring dashboard JSON into Grafana">
  <Col title="Provisioning or Git Sync">Files in a folder or a repository; Grafana reads them. Steps 2 and 3.</Col>
  <Col title="Terraform">The JSON goes into a resource; plan and apply show each change. Step 4.</Col>
  <Col title="Grafana Operator">A custom resource in Kubernetes per dashboard. A community project, not supported by Grafana Labs.</Col>
</Compare>

The command-line tool `gcx` can push resources, including JSON printed by the Foundation SDK, to any Grafana. Grizzly, an older tool for the same job, has been removed. The documentation also notes that most of these tools can be combined, for example dashboards generated by the SDK and delivered by Git Sync.

A team usually decides by who owns the dashboards. A platform team that already runs Terraform keeps dashboards there. A Kubernetes team that deploys everything with Argo CD or Flux may like the Operator. Teams whose dashboards are edited on the screen by many people get the most from Git Sync, because the screen and the repository stay one.

<Trap>
A dashboard program is code: it needs a pinned version of its library and its own review. The SDK's JSON follows the library version, so an upgrade of the library can change every dashboard it prints.
</Trap>

<Do>
1. In WSL, in your home folder, save this as `~/m16_dashboard.py`. It builds one dashboard with one time series panel per service in a list, all reading the lab's Mimir.

   ```python
   from grafana_foundation_sdk.builders.dashboard import Dashboard
   from grafana_foundation_sdk.builders.prometheus import Dataquery as PrometheusQuery
   from grafana_foundation_sdk.builders.timeseries import Panel as Timeseries
   from grafana_foundation_sdk.cog.encoder import JSONEncoder
   from grafana_foundation_sdk.models.dashboard import DataSourceRef

   SERVICES = ["checkout", "payment", "cart"]
   MIMIR = DataSourceRef(type_val="prometheus", uid="mimir")

   dashboard = (
       Dashboard("m16 generated: requests per service")
       .uid("m16-generated")
       .tags(["m16", "generated"])
       .time("now-1h", "now")
   )
   for name in SERVICES:
       dashboard = dashboard.with_panel(
           Timeseries()
           .title(f"{name} spans per second")
           .datasource(MIMIR)
           .with_target(
               PrometheusQuery().ref_id("A").expr(
                   f'sum(rate(traces_spanmetrics_calls_total{{service_name="{name}"}}[5m]))'
               )
           )
       )

   print(JSONEncoder(sort_keys=True, indent=2).encode(dashboard.build()))
   ```
2. Run it in a throw-away Python pod of the lab, which installs the pinned SDK first, and keep the JSON it prints: <Cmd>{`kubectl -n learn-m16 run fsdk --rm -i --quiet --restart=Never --image=python:3.14.7-alpine3.24 -- sh -c 'pip install -q --root-user-action=ignore --disable-pip-version-check grafana_foundation_sdk==0.0.22 && python -' < ~/m16_dashboard.py > ~/m16-generated.json`}</Cmd>
3. Count the panels and read their titles: <Cmd>{`grep -c '"type": "timeseries"' ~/m16-generated.json`}</Cmd> <Cmd>{`grep '"title"' ~/m16-generated.json`}</Cmd> One panel per service in the list, and the dashboard's own title last. Every query has `"refId": "A"`: without a reference ID, the lab's Grafana showed the panels empty and ran no query.
4. Add `"frontend"` to `SERVICES`, run action 2 again and count once more. One line of code gave a fourth panel. Then set the list back to three services and run action 2 again.
5. Keep `~/m16-generated.json`. Step 11 delivers it to Grafana.
</Do>

<Done>
A short program printed a dashboard's JSON model with one panel per service, and a change to a list changed the dashboard.

<Question id="q-m16-s05" answer="d">
A team keeps forty dashboards that differ only in a service name, and copies changes into each by hand. Which tool does Grafana's documentation recommend for generating them?

- Grafonnet, the Jsonnet library

  Grafonnet still works for some teams, but the documentation says it is not officially supported and points elsewhere.

- Grizzly, the tool for Grafana resources as files

  Grizzly has been removed and is no longer supported.

- Dashboard provisioning with `allowUiUpdates: true`

  Provisioning delivers JSON files. It does not generate forty variants of one dashboard.

- The Foundation SDK, with a loop over the service names

  The SDK builds dashboards in a programming language, so one loop can print one dashboard or panel per service.
</Question>
