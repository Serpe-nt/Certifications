<Problem>
The workshop service, a small back office for the shop, has no metrics at all. When someone says checkouts feel slow, nobody can tell how many requests it answers, how many fail, or whether the stock is running out. You are going to give it numbers.
</Problem>

<Idea>
For a service that answers requests, the Prometheus guidelines name three things to count first: requests, errors and latency. With the Python client that is one counter with route, method and status code labels, and one histogram of durations, updated once per request. A gauge for state, such as the stock, completes it.
</Idea>

## What to measure in an online service

The guidelines split services into online-serving systems, offline processing and batch jobs. The workshop service is online-serving: a client waits for every answer. For such a system the key metrics are the number of requests, the errors and the latency, and it helps to count each request when it ends, so that the count lines up with its status code and its duration.

A counter of requests with a `code` label gives you both requests and errors: the errors are the requests with a 5xx code. Add a counter for every outcome that matters to the business, such as a checkout that was placed, declined or out of stock.

## The change to the service

The folder `solutions/prometheus-client` holds the finished service. The difference from the starting point is small:

```python
HTTP_REQUESTS = Counter(
    "workshop_http_requests", "HTTP requests answered, by route, method and status code.",
    ["route", "method", "code"])
HTTP_DURATION = Histogram(
    "workshop_http_request_duration_seconds", "Time to answer an HTTP request, by route.", ["route"])
CHECKOUTS = Counter("workshop_checkouts", "Checkouts, by outcome.", ["outcome"])
STOCK = Gauge("workshop_inventory_stock", "Items in stock, by SKU.", ["sku"])
```

A Flask hook runs after every request. It takes the route template, such as `/inventory/<sku>`, from the request instead of the real path, so a thousand SKUs still make one label value. It increments the request counter, records the duration in the histogram, and for `/checkout` also counts the outcome. A new route, `/metrics`, sets the stock gauge from the database and returns `generate_latest()`, the text format of step 4.

## Where the numbers go

The service runs on your PC and listens on `127.0.0.1:8000`. The lab's Prometheus runs inside the cluster and cannot reach that address, so in this step you read the metrics on the service's own `/metrics` page, which is exactly what Prometheus would see. To scrape a target outside the cluster, the Prometheus Operator has the `ScrapeConfig` resource of step 8, and the service would have to listen on an address the cluster can reach.

<Trap practice>
The counters count every request since the service started, including your own mistakes. If your 404 count is not 2, stop the service, start it again and repeat action 3 only. Run `load.py` after you have pasted the value: it also asks for unknown SKUs.

<Remember>
For an online service, count requests by route template and status code and record their durations, once per request when it ends. Add counters for business outcomes and gauges for state, and check the result on the service's own `/metrics` page.
</Remember>

<Question id="q-m03-s11" answer="a">
A developer labels the request counter with the full path, such as `/inventory/OLJCESPC7Z`, instead of the route template. What happens as the shop grows?

- Every new SKU adds new series, so the number of series grows with the catalogue

  Each distinct path is a new label value, and each value makes its own series. The route template keeps it to one.

- Prometheus merges paths with the same prefix into one series

  Prometheus never merges label values. Each distinct value is stored as its own series.

- The client library rejects label values that contain a slash

  Label values may hold any UTF-8 characters, including slashes. Nothing stops the mistake.

- Nothing changes, because labels cost nothing until a query uses them

  Every series costs memory and disk as soon as it is stored, whether anyone queries it or not.
</Question>
