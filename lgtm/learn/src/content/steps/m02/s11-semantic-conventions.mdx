<Why>
The Java service calls the HTTP method `method`, the Go service calls it `http_verb`, and the Python service `request.type`. One dashboard for all three needs three queries, and a tool cannot know that the three names mean the same thing. Every team has invented its own words.
</Why>

<Idea>
Semantic conventions are OpenTelemetry's shared dictionary. They fix the names, types and meaning of common attributes, and the names of common spans and metrics. When every service and library uses them, one query, one dashboard and one tool work for all.
</Idea>

<Points>
  <Point label="What they define">Attribute names, their types, their meaning and their allowed values. They also define span names and kinds, and metric instruments with their units.</Point>
  <Point label="Areas they cover">HTTP, databases, messaging, RPC, cloud providers, exceptions and more. There are conventions for each signal, and for resources: the attributes that describe what produces the telemetry.</Point>
  <Point label="An HTTP example">An HTTP server span carries `http.request.method`, `http.route` and `http.response.status_code`. Its name is the method and a low-cardinality target, such as `GET /webshop/articles/:article_id`, never the full path with an ID in it.</Point>
  <Point label="service.name matters most">`service.name` is the logical name of a service, the same for every replica. If you do not set it, SDKs use `unknown_service`, so set it, for example with the `OTEL_SERVICE_NAME` variable.</Point>
  <Point label="Conventions have versions">The conventions change over time. Many older HTTP instrumentations still send the old names by default. `OTEL_SEMCONV_STABILITY_OPT_IN=http` switches them to the stable names, and `http/dup` sends both while you migrate.</Point>
  <Point label="In this lab">Mimir and Loki turn `service.name` into the label `service_name`. That is the label you saw in the "Related logs" query.</Point>
</Points>

<Trap>
Semantic conventions are not only for traces. Metrics, logs, profiles and resources have them too. And a name that looks right is not enough: the type and the meaning of the value must match as well.
</Trap>

<Question id="q-m02-s11" answer="a">
A service sends spans with `service.name` set to `unknown_service:java`. What does this tell you?

- Nobody set the service name, so the SDK used its fallback value

  SDKs fall back to `unknown_service` plus the process name when `service.name` is not set.

- The service runs an old Java version that OpenTelemetry does not support

  The fallback says nothing about the Java version.

- The collector failed to reach the backend

  Export problems do not change resource attributes.

- Java services must always use this name by convention

  The convention is the opposite: every service should set its own logical name.
</Question>
